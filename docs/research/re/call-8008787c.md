# Block at 0x8008787c

Traced fact from the USA PS-X EXE. Re-check on a disc you own with `python3 tools/entry_disasm.py build/disc/SLUS_004.91 --start 0x8008787c`. The executable and the listing stay in `build/`.

The start address is `0x8008787c`. It is not in `tools/sdk_names.txt`. `python3 tools/sdk_match.py` does not name it. The `jal` in [call-80087680.md](call-80087680.md) calls here and sets `ra` to `0x80087698`. On arrival `a0` is 1, `a1` is 1, and `a2` is `0xa`. Both `beq` tests are not taken. The hard cap is 64 instructions. This block ends at `jr ra` before the cap.

`beq` at `0x8008787c` compares `a1` with zero. `a1` is 1, so the branch is not taken. The delay slot writes `0xe1000000` into `v1`. `ori` at `0x80087884` sets `v1` to `0xe1000200`. `beq` at `0x80087888` compares `a0` with zero. `a0` is 1, so the branch is not taken. The delay slot keeps the bits of `a2` selected by `0x9ff`, so `v0` is `0xa`. `ori` at `0x80087890` sets `v0` to `0x40a`.

`jr` returns through `ra`. The delay slot joins `v1` into `v0`, so `v0` is `0xe100060a`. `ra` is `0x80087698`. This block does not store that word.

After the delay slot, control goes to `0x80087698`. `v0` is `0xe100060a`. The words there are not traced. The display x and y halfwords are still not quoted. This note does not close the gap in `components/exe/load.cpp`.
