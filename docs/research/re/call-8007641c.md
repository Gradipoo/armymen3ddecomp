# Display-loop continuation at 0x8007641c

This follows the first display fill in [call-80076274.md](call-80076274.md).
The caller's saved state is `s0` 1, `s1` `0x800e0000`, and `s2` zero.
The established display-buffer count is 2. This note follows that state;
it is not a runtime debugger observation.

The load at `0x8007641c` reads the count from `0x800e15b0`. It replaces the
unused return value from `DrawPrim`. After the load delay, an unsigned
comparison tests the completed count in `s0` against this reloaded value.
With the recorded count of 2, the branch at `0x80076428` is taken to
`0x8007640c`. Its delay slot is a nop. This is a loop back edge. The count
is read again after each fill rather than cached across calls.

The call at `0x8007640c` targets `0x80076164`. Our SDK matcher does not name
that target. It sets the return address to `0x80076414`. Its delay slot
increments `s0` to 2. The volatile argument registers left by `DrawPrim`
are unknown here. `s2` retains the original color argument, zero.

This note covers seven executed instructions including delay slots. It
stops at the first unnamed call. The second pass through the callee is in
[call-80076164-second.md](call-80076164-second.md). Existing notes for the
first pass stay unchanged. Re-check the caller with the local executable
and instruction tool. Listings stay under `build/`.
