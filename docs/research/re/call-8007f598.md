# Block at 0x8007f598

Traced fact from the USA PS-X EXE. Re-check on a disc you own with `python3 tools/entry_disasm.py build/disc/SLUS_004.91 --start 0x8007f598`. The executable and the listing stay in `build/`.

The start address is `0x8007f598`. It is not in `tools/sdk_names.txt`. `python3 tools/sdk_match.py` does not name it. The `jal` in [call-80087210.md](call-80087210.md) calls here and sets `ra` to `0x800872d4`. On arrival `a0` is `0x800b7634`, `a1` is `0x800e15dc`, and `a2` is `0x14`. `s0` is `0x10`. `s1` is `0x800e15dc`. `s2` is `0x102`. `python3 tools/boot_slice.py` stopped at the first `beq` because it did not have `a0`. This note uses that `a0` and follows the known side. The backward branch is the word loop. The tool stops when that branch returns to an instruction already in this slice. `t0` starts at 5, so the same loop runs five times and then falls through. The hard cap is 64 instructions. The five passes stay inside that cap.

`beq` at `0x8007f598` compares `a0` with zero. `a0` is `0x800b7634`, so the branch is not taken. The delay slot copies `a0` into `v0`, so `v0` is `0x800b7634`. `beq` at `0x8007f5a0` compares `a1` with zero. `a1` is not zero, so it is not taken. `beq` at `0x8007f5a8` compares `a2` with zero. `a2` is `0x14`, so it is not taken. The delay slot sets `t0` to 7. `slt` leaves `at` at 1, because 7 is below `0x14`. `beq` at `0x8007f5b4` is not taken. The delay slot keeps the low 2 bits of `a0`. Those bits are 0, because `0x800b7634` is a multiple of 4. `beq` at `0x8007f5bc` is taken. The byte loop at `0x8007f5cc` does not run. The delay slot sets `t1` to 4.

`srl` at `0x8007f5e4` shifts `a2` right by 2, so `t0` is 5. `andi` of `a1` leaves `t1` at 0, because `0x800e15dc` is a multiple of 4. `bne` at `0x8007f5ec` is not taken. The delay slot keeps the low 2 bits of `a2`, so `a2` becomes 0. The unaligned word path at `0x8007f61c` does not run.

The loop at `0x8007f5f4` loads one word from `a1`, adds 4 to `a1`, stores that word through `a0`, subtracts 1 from `t0`, and adds 4 to `a0` in the delay slot. It repeats while `t0` is not 0. Five passes copy `0x14` bytes from `0x800e15dc` to `0x800b7634`. The first source word is the display x and y halfwords. This note does not quote that word, so it does not state the word stored at `0x800b7634`. The word at `0x800e15e0` is `0x00f00200`: [call-8008abbc.md](call-8008abbc.md) stored `0x200` at `0x800e15e0` and `0xf0` at `0x800e15e2`. That word is stored at `0x800b7638`. The words at `0x800e15e4` and `0x800e15e8` are 0, and the word at `0x800e15ec` is 0. Those three words are stored at `0x800b763c`, `0x800b7640`, and `0x800b7644`. This replaces the `0xff` bytes [call-8008915c.md](call-8008915c.md) stored from `0x800b7634` through `0x800b7647`.

After the fifth pass `t0` is 0, so the branch is not taken. `a0` is `0x800b7648` and `a1` is `0x800e15f0`. `beq` at `0x8007f60c` is taken because `a2` is 0. The byte loop at `0x8007f640` does not run. `jr` at `0x8007f658` returns through `ra`. The delay slot is `nop`. `ra` is `0x800872d4`. `v0` stays `0x800b7634`.

After the delay slot, control goes to `0x800872d4`. `v0` is `0x800b7634`. `a0` is `0x800b7648`. `a1` is `0x800e15f0`. `a2` is 0. The words at `0x800872d4` are not traced. The saved `ra` at `0x800761dc` is not loaded by this body. This note does not close the gap in `components/exe/load.cpp`.
