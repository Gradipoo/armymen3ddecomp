# Fallthrough at 0x800650a8

[call-80065098.md](call-80065098.md) records `beq` at `0x800650a0` when the
`0x80` bit test on complemented input is nonzero. The fallthrough target is
this address. The taken target is `0x800650b4`. This note covers the
fallthrough only. It does not resume the parked static boot.

`python3 tools/boot_slice.py build/disc/SLUS_004.91 --start 0x800650a8 --max 64`
reports six instructions and stops at an unknown branch. The report stays in
`build/`.

| Address | Instruction |
| --- | --- |
| `0x800650a8` | `addiu v0, zero, -0x80` |
| `0x800650ac` | `j 0x800650cc` |
| `0x800650b0` | `sb v0, 0xa(s0)` |
| `0x800650cc` | `andi v0, a0, 0x10` |
| `0x800650d0` | `beq v0, zero, 0x800650e0` |
| `0x800650d4` | `addiu v0, zero, -0x80` |

The delay slot at `0x800650b0` stores the low byte of `v0` at offset `0x0a`
on the record base `s0`. After `addiu`, that byte is `0x80`. Control joins
the path at `0x800650cc` that [call-800650d0.md](call-800650d0.md) documents
from the `0x10` test. `beq` at `0x800650d0` is unknown. This note stops
there. It does not enter either target.

The slice contains no `jal`.

## Our code

`components/exe/call_800650a8.cpp` stores `0x80` at offset `0x0a` on the
record. Glue in `menu_input_scan_step` calls it after
[call-80065098](call-80065098.md) when the `0x80` bit is set, then runs the
same complemented bit tails as the `s6` zero path from `0x800650cc`.

## Gap

The shared `beq` at `0x800650d0` and later tails stay in
[call-800650d0.md](call-800650d0.md) and the sibling tail notes. This block
does not state live complemented input on the `s6` nonzero path.
