# Fallthrough at 0x80064dd8

[call-80064dc8.md](call-80064dc8.md) records the not-taken `bne` at `0x80064dd0`
when the first `lbu` at `s1` is zero. That path lands here. Live `s1` on entry
is one past the address used in the `0x80064dc8` load from the delay slot at
`0x80064dd4`. This note does not resume the parked static boot.

`python3 tools/boot_slice.py build/disc/SLUS_004.91 --start 0x80064dd8 --max 64`
reports five instructions and stops at the unknown `bne` at `0x80064de4`. The
report stays in `build/`.

| Address | Instruction |
| --- | --- |
| `0x80064dd8` | `lbu v0, 0x0(s1)` |
| `0x80064ddc` | `addiu v1, zero, 0x80` |
| `0x80064de0` | `andi v0, v0, 0xf0` |
| `0x80064de4` | `bne v0, v1, 0x80064dfc` |
| `0x80064de8` | `addiu t1, zero, 0x1` |

The delay slot at `0x80064de8` always runs and sets `t1` to one. The taken
target is `0x80064dfc`. The fallthrough is `0x80064dec`. Live masked `v0` and
the `bne` side are not stated from retail capture. The slice contains no `jal`.

## Our code

`components/exe/call_80064dd8.cpp` loads one byte through an optional test
pointer, masks with `0xf0`, compares to `0x80`, records the delay-slot `t1`,
and records `branch_to_64dfc` or `entered_64dec`.

`menu_input_scan_step` calls this block after [call-80064dc8](call-80064dc8.md)
when `loop_body_64dc8.entered_64dd8` is true. Optional `test_inject_s1_lbu`
supplies the byte at the post-dc8 `s1` in ctests only. Glue passes
`test_inject_s1_lbu + 1` when the inject pointer is non-null so the first byte
still drives the `0x80064dc8` load. Live retail bytes at `s1` are not stated.

## Gap

Instructions at `0x80064dfc` and `0x80064dec` are not traced. The `beq` at
`0x80064e0c` on the merged path at `0x80064e04` is not modeled.
