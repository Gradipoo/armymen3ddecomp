# Block at 0x800752e8

[call-8005cc88.md](call-8005cc88.md) returns here. `v0` is 0. The word at `0x800e152c` is 0, so this boot does not reach this address. This is the other side of table index 5.

`beq v0, zero, 0x8007542c` is taken. The delay copies `s0` into `v0`. [call-80075198-3.md](call-80075198-3.md) and [call-80075198-4.md](call-80075198-4.md) state that `s0` as a stack address. The other `a0` 5 entries do not state `s0`. This note does not turn that stack address into a number.

The landing point `0x8007542c` is the epilogue from [call-80075198.md](call-80075198.md), starting at the load of `ra`. Saved `ra` is `0x80062514` for the entries that arrived from `0x800624cc`, and `0x80062548` for the entries that arrived from `0x80062514`. `jr ra` returns to that saved address. `v0` stays the copied `s0`. The instructions at `0x800752f0` are not this side.

The 8 bytes at `0x800752e8` and `0x800752ec` also occur at `0x800330ac`. This note covers only the copy at `0x800752e8`.

## Our code

`call_800752e8` returns `s0` when the result is 0. The host check uses `s0` 0x24 as a stand-in, not a traced register value.

## Gap

The callers at `0x80062514` and `0x80062548` are not resumed. `v0` is the arriving `s0`, and that value is not a stated number. The `0x43` path in [call-8005ca00.md](call-8005ca00.md) is not these strings.
