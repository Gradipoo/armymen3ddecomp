# Block at 0x80025228

Traced fact from the USA PS-X EXE. Re-check on a disc you own with `python3 tools/entry_disasm.py build/disc/SLUS_004.91 --start 0x80025228`. The executable and the listing stay in `build/`.

The start address is `0x80025228`. The `jal` at `0x80025220` set `ra` to this address, and the `jr` at `0x8007faf0` returned here. That return is in [call-8007faf0.md](call-8007faf0.md). The tool followed 4 instructions and stopped at the first branch. The hard cap is 64 instructions. This block ended before the cap.

`lui` at `0x80025228` loads `0x80080000` into `s2`. `lw` at `0x8002522c` reads the word at `-0x658(s2)` into `v0`, so `v0` is the word at `0x8007f9a8`. `nop` at `0x80025230` sits between that load and the branch that reads `v0`. `beq` at `0x80025234` branches to `0x8002524c` when `v0` is 0. When `v0` is not 0, the branch is not taken. The delay slot at `0x80025238` is `addiu v1, s2, -0x658`, so `v1` becomes `0x8007f9a8` on both paths. Re-check it with `--start 0x80025238`. That run's first instruction is the `addiu`. The words after that instruction are not traced. The fall-through address is `0x8002523c`.

The word at `0x8007f9a8` was stored by the block in [entry-after-third-compare.md](entry-after-third-compare.md). Whether that word is 0 is unknown, because the BIOS ROM is not in this tree. The `addiu` writes `v1` and leaves both targets unchanged. The branch reads `v0`.

This block writes `s2`, `v0`, and `v1`. It reads `s2` and the word at `0x8007f9a8`. It does not read or write `sp` or the stack slots saved at `0x800251f8`. The bodies at `0x8002523c` and `0x8002524c` are not traced. The caller return at `0x8007faec` is not traced. This note does not close the gap in `components/exe/load.cpp`.
