# Caller continuation at 0x80064e58

This is a partial caller record, not a complete function. The earlier
[submission observation](call-8007c11c.md) measured named `PadGetState`
at `0x80094fe0`, with `a0=0` and return address `0x80064e58`.
The SDK body was not entered. Prepared slices and capture records remain
local under `build/coordination/menu-button-path/`.

At `0x80064e58`, the caller copies the return value into `s2` and tests
whether it is unsigned less than seven. The branch at `0x80064e60` takes
`0x80064f14` when the test is false. Its delay slot loads `0x800c0000`
into `v0`. Static slicing stopped at this unknown branch.

The first gated capture sampled frames 3628 through 4227. All 600 return
samples had `v0=2`. All 600 branch samples had `s2=2` and `v0=1`, so the
sampled branch falls through to `0x80064e68`. The hook stopped at frame
4228 with zero errors and overflow. The principal observed NEW GAME,
pressed Down for 100 ms, and observed OPTIONS. Retained frames 3600 and
4200 show those selections. The exact guest input edge was not measured.
The status value alone does not identify button bits or selection state.

The fallthrough constructs table address `0x800c3e98`, indexes it by
`s2*4`, and loads an indirect destination. A load-delay nop precedes
`jr v0` at `0x80064e7c`, followed by another nop. The slice stops there.
For the sampled index two, the table word address is `0x800c3ea0`.
Executable file contents are not used as the live value of that word.

A second capture expired at its ungated frame limit of 7200 while the
principal still observed loading. It recorded no dispatch samples and
zero errors. That attempt is preserved. A retry extends the startup
allowance while retaining a 600-frame gated measurement.

The retry captured 600 dispatch observations, frames 3718 through 4317.
Every sample had `s2=2`, live destination `v0=0x80064f14`, and
`s1=0x800e18d8`. The hook stopped at frame 4318 with zero errors and
overflow. The principal again observed NEW GAME, opened the gate, pressed
Down for 100 ms, and observed OPTIONS. The process was interrupted after
the measurement, exit 255. This resolves the indirect destination for
these samples, without claiming every controller state takes this path.

A prepared slice from that measured destination loads an unsigned byte
through `s1`, then waits through a load-delay nop. The branch at
`0x80064f1c` takes `0x80065144` when the byte is nonzero. Its delay slot
increments `s1` by one. The byte was not captured; its meaning and the
branch direction remain unknown. No instruction beyond that branch was
followed. The next observation needs that loaded byte at the branch.

These captures use the local status-accessor PCSX-Redux build described in
[the accessor record](live-gpu-status-accessor.md), the owner's USA disc,
full boot with interpreter, and the recorded local BIOS. Both card slots
use fresh copies of the retained initial card files. Guest-visible card
contents were not independently verified. Identity limits from the
[first screen record](first-screen-observation.md) still apply. Captures,
hashes, launch arguments, and raw reports stay local.

No game function is implemented or promoted by these observations. The
button read and selection update remain unresolved. The parked static
boot lane is unchanged.
