# Shared tail at 0x80065168

[call-80064f78.md](call-80064f78.md) records the taken `beq` at `0x80064f7c`
when the masked complement of the halfword is zero. That path lands here
without the mask stores at `0x80064f8c`. This note does not resume the
parked static boot.

`python3 tools/boot_slice.py build/disc/SLUS_004.91 --start 0x80065168 --max 64`
reports eleven instructions and stops at the unknown branch at `0x8006518c`.
The report stays in `build/`.

The Up path and the cleared `0x40` path reach the same tail from
`0x8006516c` after record stores and `call_8006471c`. This entry skips
those caller-specific steps and starts at the `0x7c` advance.

The word at `sp+0x1c` is the loop limit for `slt` at `0x80065188`. Its
live retail value is not stated. The delay slot at `0x80065190` stores
the incremented `sp+0x28` word on either branch side.

## Our code

`components/exe/call_80065168.cpp` advances the record by `0x7c`, updates
`MenuInputScanState` like the d0, ec, and f4 tails, and returns
`menu_scan_should_loop` with the caller-supplied `stack_word_1c` limit.
An optional `stack_word_28` pointer models the load, add four, and store
at `sp+0x28`. When the pointer is null, `table_cursor` still advances
four and the live stack word stays unhooked.

`menu_input_scan_step` enters this block when `compare_four_to_65168` is
true from [call-80064f78.md](call-80064f78.md).

## Gap

The taken loop at `0x80064e40` is recorded in [call-80064e40.md](call-80064e40.md).
This block does not enter it. The fallthrough at `0x80065194` is recorded
in [call-80065194.md](call-80065194.md). Glue records exit when the
compare stops the loop. Live retail values at `sp+0x1c` and `sp+0x28`
stay unstated.
