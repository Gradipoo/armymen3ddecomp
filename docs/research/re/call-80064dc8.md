# Branch body at 0x80064dc8

[call-800651c8.md](call-800651c8.md) records the taken `bne` at `0x800651d8`
when `sp+0x18` is below two after increment. That path lands here with retail
`s1` set to `v0 + 0x18fa` on entry (`0x800e18fa` when `v0` is `0x800e0000` from
the delay slot at `0x80065198`). This note does not resume the parked static
boot.

`python3 tools/boot_slice.py build/disc/SLUS_004.91 --start 0x80064dc8 --max 64`
reports four instructions and stops at the unknown `bne` at `0x80064dd0`. The
report stays in `build/`.

| Address | Instruction |
| --- | --- |
| `0x80064dc8` | `lbu v0, 0x0(s1)` |
| `0x80064dcc` | `nop` |
| `0x80064dd0` | `bne v0, zero, 0x80065194` |
| `0x80064dd4` | `addiu s1, s1, 0x1` |

The delay slot at `0x80064dd4` always runs. Live `s1` after the step is one
past the load address on either `bne` side. The taken target is
`0x80065194`. The fallthrough is `0x80064dd8`. The slice contains no `jal`.

## Our code

`components/exe/call_80064dc8.cpp` loads one byte through an optional test
pointer, applies the delay-slot `s1` bump, and records `branch_to_65194` or
`entered_64dd8`. When the pointer is null, the load is zero and the not-taken
side is recorded.

`menu_input_scan_step` calls this block after `call_800651c8` when
`loop_taken_651c8.branch_to_64dc8` is true. Optional `test_inject_s1_lbu` supplies
the byte in ctests only. Live retail bytes at `s1` are not stated. When
`entered_64dd8` is true, glue calls [call-80064dd8](call-80064dd8.md).

## Gap

The second pass at `0x80065194` on the taken `bne` is not modeled.
