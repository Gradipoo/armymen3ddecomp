# Block at 0x800879cc

Traced fact from the USA PS-X EXE. Re-check on a disc you own with `python3 tools/entry_disasm.py build/disc/SLUS_004.91 --start 0x800879cc`. The executable and the listing stay in `build/`.

The start address is `0x800879cc`. It is not in `tools/sdk_names.txt`. `python3 tools/sdk_match.py` does not name it. The `jal` in [call-8008766c.md](call-8008766c.md) calls here and sets `ra` to `0x80087680`. On arrival `a0` is 0 and `a1` is `0xf0`. There is no branch. The tool followed 6 instructions and stopped at `jr ra`. The hard cap is 64 instructions. This block ended before the cap.

`andi` keeps the low 11 bits of `a1`, which stay `0xf0`. `sll` by 11 leaves `a1` as `0x78000`. `andi` keeps the low 11 bits of `a0`, so `v0` is 0. `lui` writes `0xe5000000` into `v1`. `or` joins that into `v0`. `jr` returns through `ra`. The delay slot joins `a1` into `v0`, so `v0` is `0xe5078000`. This block does not store that word.

After the delay slot, control goes to `0x80087680`. `v0` is `0xe5078000`. The words there are not traced. The display x and y halfwords are still not quoted. This note does not close the gap in `components/exe/load.cpp`.
