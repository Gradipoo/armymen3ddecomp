# Fallthrough at 0x80064f78

This block runs when the word at `0x800dd730` equals four at the `bne`
at `0x80064f70`. [call-80064f48.md](call-80064f48.md) records the
measured menu path with that word zero, so execution took `0x80064f8c`
instead.

The delay slot at `0x80064f74` is `nor a0, zero, a1`, so `a0` holds the
bitwise complement of the halfword loaded in the parent block. At
`0x80064f78`, `andi` keeps `0xfff9` of `a0` in `v0`. The `beq` at
`0x80064f7c` compares that result with zero and targets `0x80065168`.
The delay slot at `0x80064f80` is `addiu v0, zero, 0x1`, so `v0` is one
whether the branch is taken or not. This note stops before `0x80065168`.
That target is not entered here.

## Our code

`components/exe/call_80064f78.cpp` masks the complemented halfword, records
whether the `beq` would target `0x80065168`, and sets `v0` to one from the
delay slot. `menu_input_scan_step` records `compare_four_ran` when this
path runs and does not enter the mask stores at `0x80064f8c`.
