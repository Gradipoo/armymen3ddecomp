# Return at 0x8007a5a4 and the repeated cursors

Traced fact from the USA PS-X EXE. Re-check on a disc you own with `python3 tools/entry_disasm.py build/disc/SLUS_004.91 --start 0x8007a5a4`. The executable and the listing stay in `build/`.

The start address is `0x8007a5a4`. The `jal` in [call-8007a540-10.md](call-8007a540-10.md) returns here through [call-8007a4e4-9.md](call-8007a4e4-9.md). `v0` is `0x800b5d78`. `s0` is `0x800b3b60`. `s2` is `0x80010024`. `s3` is 0. `s4` is `0x8001007c`. The frame at `0x800251f8` stays open. Its saved `ra` stays `0x8007faec`.

The return matches [call-8007a5a4-20.md](call-8007a5a4-20.md), so `s2` becomes `0x80010028`. The laps from `0x80010028` through `0x8001003c` match [call-8007a570-21.md](call-8007a570-21.md) through [call-8007a5a4-27.md](call-8007a5a4-27.md). Those slots were not swapped again. `s2` becomes `0x80010040`. This note does not disassemble `0x8007a4e4` again.

The live word at `0x80010040` is `0x800b5b64`, from [call-8007a668-9.md](call-8007a668-9.md). [call-8007a570-28.md](call-8007a570-28.md) saw `0x800b5ce4` there. The next lap is the next note. The caller return at `0x8007faec` is not traced.
