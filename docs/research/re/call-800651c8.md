# Taken path at 0x800651c8

[call-80065194.md](call-80065194.md) records the taken `bne` at `0x80065194` when
retail `s5` is not zero. That path lands here. The delay slot at `0x80065198`
still runs `lui v0, 0x800e` before the branch, so live `v0` on entry is
`0x800e0000`. This note does not resume the parked static boot.

`python3 tools/boot_slice.py build/disc/SLUS_004.91 --start 0x800651c8 --max 64`
reports six instructions and stops at the unknown `bne` at `0x800651d8`. The
report stays in `build/`.

| Address | Instruction |
| --- | --- |
| `0x800651c8` | `lw t0, 0x18(sp)` |
| `0x800651cc` | `addiu s1, v0, 0x18fa` |
| `0x800651d0` | `addiu t0, t0, 0x1` |

| `0x800651d8` | `bne v0, zero, 0x80064dc8` |

Fallthrough is `0x800651e0`. Glue enters [call-80064dc8](call-80064dc8.md) on
the taken side.

## Our code

`components/exe/call_800651c8.cpp` loads and increments the word at `sp+0x18`
through an optional `stack_word_18` pointer, sets `s1` to `v0 + 0x18fa`,
evaluates `slti` against two, stores the incremented word in the delay slot,
and records `branch_to_64dc8` or `entered_651e0`.

`menu_input_scan_step` calls this block after `call_80065194` when
`loop_exit.branch_to_651c8` is true. Entry `v0` is `0x800e0000` from the
65194 delay slot. `MenuInputScanState::index` is retail `s5` at the branch.
When `branch_to_64dc8` is true, glue calls [call-80064dc8](call-80064dc8.md).
When [call-80064dc8](call-80064dc8.md) records `entered_64dd8`, glue calls
[call-80064dd8](call-80064dd8.md). When that block records `branch_to_64dfc`,
glue calls [call-80064dfc](call-80064dfc.md). When it records
`entered_64dec`, glue calls [call-80064dec](call-80064dec.md). When either
path records `entered_64e14`, glue calls [call-80064e14](call-80064e14.md).

## Gap

Instructions at `0x800651e0` are not traced. Live retail words at `sp+0x18` on
this path are not stated.
