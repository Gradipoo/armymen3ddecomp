# First-byte branch at 0x80065144

The [caller at `0x80064f14`](call-80064f14.md) branches here when the first
loaded table byte is nonzero. The delay slot at `0x80064f1c` advances `s1`
by one. This note stops before the unknown branch at `0x8006518c`.

Prepared slice:

```
python3 tools/boot_slice.py build/disc/SLUS_004.91 --start 0x80065144 --ra 0x80064f20
```

| Address | Instruction |
| --- | --- |
| `0x80065144` | `lui t0, 0x800e` |
| `0x80065148` | `addiu t0, t0, -0x28f8` |
| `0x8006514c` | `lw v0, 0x28(t0)` |
| `0x80065150` | `addiu t1, zero, 4` |
| `0x80065154` | `beq v0, t1, 0x80065164` |

`t0` is `0x800dd730`. That word is the compare input reused in
[call-80064f48.md](call-80064f48.md). Captured menu samples had it zero.

When `v0 != 4`, fallthrough calls unnamed `0x800645a8` with `a0=s5`, then
continues at [`0x80065164`](call-80065164.md). When `v0 == 4`, control
enters `0x80065164` directly.

## Our code

`call_80065144` compares the host `compare_word_dd730` argument with four.
`menu_input_scan_step` invokes [call-800645a8.md](call-800645a8.md) on the
fallthrough side, then [call-80065164.md](call-80065164.md). The live byte
at the first branch is not captured in retail traces yet.
