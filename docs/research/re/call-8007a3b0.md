# Call at 0x8007a3b0

Traced fact from the USA PS-X EXE. Re-check on a disc you own with
`python3 tools/entry_disasm.py build/disc/SLUS_004.91 --start 0x8007a3b0`.
The executable and the listing stay in `build/`.

This is the return site after the `jal` in [call-8007a384.md](call-8007a384.md).
The callee is [call-8007a250.md](call-8007a250.md). Arriving `v0` is 0.
`s1` is `0x8009f368`, `s0` is `1`, `s3` is `0x80010db0`, and `s2` is `0`.
`a2` is `0x80010db0` and `a3` is `0`. The word at `0x8009f368` is already
`2`. The frame opened at `0x8007a384` is still open. The saved `ra` at
`0x28(sp)` is `0x80010e24`.

The start address is `0x8007a3b0`. The tool follows straight-line words
until the first jump. It followed 2 instructions and stopped at the `jal`.
The hard cap is 64 instructions. This block ended before the cap. The
delay slot is the next word, at `0x8007a3b8`. Re-check it with
`--start 0x8007a3b8`. That run's first instruction is the `addiu`. This
note covers those 3 instructions.

`addu` at `0x8007a3b0` copies `s1` into `a0`, so `a0` is `0x8009f368`. It
does not read `v0`. `v0` stays 0.

`jal` at `0x8007a3b4` targets `0x8007a2b0` and sets `ra` to `0x8007a3bc`.
The delay slot at `0x8007a3b8` is `addiu a1, sp, 0x10`, so `a1` is the
address of the stack slot at `0x10(sp)`. This block does not store that
slot. The prologue did not write `0x10(sp)`. `python3 tools/sdk_match.py`
has no name for `0x8007a2b0`. The BIOS table in [bios.md](bios.md) has no
name for it. This note stops at the call and its delay slot. The next
address is `0x8007a2b0`.

These words write `a0`, `a1`, and `ra`. They read `s1` and `sp`. They do
not read `v0`, `s0`, `s2`, `s3`, `a2`, or `a3`. `a2` stays `0x80010db0`.
`a3` stays `0`. `s0` stays `1`. `s2` stays `0`. `s3` stays `0x80010db0`.
The body at `0x8007a2b0` is not entered. The words at `0x8007a3bc` are not
traced.

## Our code

`components/exe/call_8007a3b0.cpp` copies the saved pointer into `a0` and
passes the address of the stack slot as `a1`. `a2` and `a3` stay as they
arrived. The retail target is `0x8007a2b0`. That body stays a gap in the
file. A host check uses `0x8009f368`, `0x80010db0`, and `0`. The check
uses a local function. It does not run the retail callee.
