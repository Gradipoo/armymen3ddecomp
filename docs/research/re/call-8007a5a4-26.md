# Return at 0x8007a5a4 and the repeated cursors

Traced fact from the USA PS-X EXE. Re-check on a disc you own with `python3 tools/entry_disasm.py build/disc/SLUS_004.91 --start 0x8007a5a4`. The executable and the listing stay in `build/`.

The start address is `0x8007a5a4`. The `jr` path in [call-8007a4e4-12.md](call-8007a4e4-12.md) returns here from the `jal` in [call-8007a540-9.md](call-8007a540-9.md). `v0` is `0x800b5da0`. `s0` is `0x800b5b58`. `s2` is `0x80010020`. `s3` is 0. `s4` is `0x8001007c`. The frame at `0x800251f8` stays open. Its saved `ra` stays `0x8007faec`.

The return matches [call-8007a5a4-19.md](call-8007a5a4-19.md), so `s2` becomes `0x80010024`. The laps from `0x80010024` through `0x80010038` match [call-8007a570-20.md](call-8007a570-20.md) through [call-8007a5a4-25.md](call-8007a5a4-25.md). Those slots were not swapped. `s2` becomes `0x8001003c`. This note does not disassemble `0x8007a4e4` again.

The live word at `0x8001003c` is `0x800b599c`, from [call-8007a688-6.md](call-8007a688-6.md). [call-8007a570-26.md](call-8007a570-26.md) saw `0x800b5c8c` there. The next lap is the next note. The caller return at `0x8007faec` is not traced.
