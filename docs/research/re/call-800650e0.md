# Caller released path at 0x800650e0

The [Up path](call-800650d0.md) covers the fallthrough at `0x800650d8` when
`a0 & 0x10` is nonzero. The [released-input record](call-80064f24.md)
followed every complemented bit test through `0x800650d0` with zero
results and continued at `0x800650e0`. This note starts there. It covers
3 instructions through the delay slot of the unknown branch. It does not
resume the parked static boot.

`andi` at `0x800650e0` keeps bit `0x40` of complemented input `a0` in
`v0`. `beq` at `0x800650e4` compares that result with zero. The taken
address is `0x800650f4`. The fallthrough is `0x800650ec`. The delay slot
at `0x800650e8` sets `v0` to `0x7f` on either side. `a0` is not stated at
this entry, so the branch is unknown. This note stops. It does not enter
either block.

The slice contains no `jal`. [call_8006471c](call-8006471c.md) is not
reached here.

## Our code

`components/exe/call_800650e0.cpp` applies the `0x40` test. The delay
slot value `0x7f` is stored when glue enters
[call-800650ec](call-800650ec.md). The taken block when bit `0x40` is
clear is recorded in [call-800650f4.md](call-800650f4.md).

## Gap

This span does not follow the `beq` at `0x800650e4` into either target.
The branch outcome is stated only through glue that calls `call_800650f4`
or `call_800650ec`.
