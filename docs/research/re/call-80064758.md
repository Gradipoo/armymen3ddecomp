# Call at 0x80064758

This block is the fallthrough of `beq` at `0x80064750` in [call-8006471c.md](call-8006471c.md). That note does not state the halfword at `0x800dd764`. This note assumes that branch was not taken, so execution reaches `0x80064758`. The assumption is only for this static slice. It does not choose the taken side at `0x800647c4`.

From the caller span, `t0` and `a0` are `0x800dd748`, `a2` is 1, `a3` is 0, `t1` is 0, and `ra` is `0x8006510c`. This block does not write `sp`.

`lhu` at `0x80064758` reads the unsigned halfword at `t0+4`, address `0x800dd74c`. This note does not state that halfword. The delay slot at `0x8006475c` is `nop`. `and` at `0x80064760` keeps the bits of that halfword that are set in `a2`. With `a2` equal to 1, that is the low bit.

After `and` at `0x80064760`, `beq v0,zero` at `0x80064764` compares that masked result with 0. The delay slot at `0x80064768` is `nop`.

**Taken `0x800647b8`:** `lhu` at `a0+0x3c`, `sh` to `a0+0x1c`, then execution falls into `0x800647c4` (wait loop modeled in [call-8006471c.md](call-8006471c.md), not duplicated here).

**Fallthrough `0x8006476c`:** `lhu` at `a0+0x1c`, `subu v1,v0,a1`, `bgtz v1,0x800647b0`. At `0x800647b0`: `j 0x800647c4` with delay-slot `sh v1,0x1c(a0)`. Register `a1` holds the low 16 bits of the caller word (`andi` in [call-8006471c.md](call-8006471c.md)).

**Not taken `0x80064778`:** `v1` still holds `halfword_at_1c - a1_low16` from the unsigned `subu`. Prepared slice from `0x80064778` in `build/boot-slice.txt` when the EXE is present.

- `0x80064780` `lhu v0,0x5c(a0)`
- `0x80064788` `addu v1,v1,v0`
- `0x8006478c` `bgtz v1,0x80064798`. Taken: `sh v1,0x1c(a0)` at `0x80064798`. Not taken: `0x80064794` `addiu v1,zero,1` then `0x80064798` stores `v1` at `0x1c(a0)`.
- `0x8006479c` `lhu v0,0x6(t0)` with `t0` the record base (`0x800dd748` for index 0); host `record_bytes+6`.
- `0x800647a4` `or v0,v0,a2`
- `0x800647a8` `j 0x800647c4`, delay slot `sh v0,0x6(t0)`.

This note does not enter the wait loop at `0x800647c4`. That loop stays in [call-8006471c.md](call-8006471c.md).

The 20 bytes from `0x80064758` through `0x80064768` occur once in the executable.

## Our code

`components/exe/call_80064758.cpp` applies the mask from `a2` to a caller-supplied halfword (retail `lhu` at record+4). When the masked value is zero it models the `0x800647b8` copy from offset `0x3c` to `0x1c` and sets `continues_at_647c4`. Otherwise it loads offset `0x1c`, subtracts `a1_low16`, and when the difference is positive models `0x800647b0` storing the difference at `0x1c` before `0x800647c4`. When that `bgtz` is not taken it models `0x80064780` through the `j` at `0x800647a8`: add offset `0x5c`, store at `0x1c` per `0x80064798`, `or` offset `0x6` with the mask, store at offset `0x6`, and set `continues_at_647c4`. Without `record_bytes`, branch flags follow the compares but no host buffer writes run. Return value is always `halfword & mask`. The record buffer must span at least `0x5e` bytes for loads at `0x5c` and stores at `0x6`.
