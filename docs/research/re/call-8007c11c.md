# Function at 0x8007c11c

The USA executable inventory lists this entry and a 96-byte body. Prepared
slices cover its 24 instructions through `jr ra` and its delay slot. Reports
remain under `build/coordination/menu-update-slice/run2/`. SDK bodies were
not entered. The static boot's parked forward lane was not resumed.

## Calls and branch

The function saves the arriving table address and count, then calls named
`DrawSync` at `0x800865c8` from `0x8007c134`. Argument `a0` is zero; return
address is `0x8007c13c`. Its return value is not used by this function.

The instruction at `0x8007c13c` loads the word at `gp+0x0c`, followed by a
load-delay nop. The `beq` at `0x8007c144` takes `0x8007c158` when that word
is zero. Its delay slot is nop. The word must be read after DrawSync, not
cached before that call.

The nonzero path constructs callback address `0x8007c00c`. It calls named
`DrawSyncCallback` at `0x800864d0` from `0x8007c150`, with that address in
`a0` and return address `0x8007c158`. The return value is not used. The
callback body already has [a separate note](call-8007c00c.md); this review
does not enter it. This branch is supported by static instruction research but
was not observed in the menu capture below.

Both paths compute the final ordering-table address as arriving `a0` plus
four times arriving `a1` minus four, modulo 32 bits. `jal` at `0x8007c160`
calls named `DrawOTag` at `0x80086bbc`, with the addition completed in its
delay slot. Return address is `0x8007c168`. The epilogue restores the saved
registers and returns through `ra` at `0x8007c174`, releasing the frame in
its delay slot. It does not replace `v0`, so the DrawOTag return passes
through opaquely. No fixed return value is asserted.

Zero count retains the retail unsigned wrap behavior. This function does
not validate the table or replace guest addresses with host pointers.

## Menu observation

The principal observed `NEW GAME`, opened the capture gate, pressed Down
for 100 ms, and observed `OPTIONS`. Retained frames 3360 and 3960 were
independently inspected and show those selections. The host press duration
and frame bracket do not identify the exact guest button edge.

During the 600-frame gated interval, frames 3370 through 3969, all 600
entry observations returned to `0x8005e27c`. Arriving `a0` alternated between
`0x800c8518` and `0x800ca918`; `a1` was `0x900`. At the branch, `gp` was
`0x800c5424` and the loaded `v0` was zero in every sample. Thus the sampled
branch takes the zero path. Corresponding DrawOTag addresses alternated
between `0x800ca914` and `0x800ccd14`, matching the expression above.
The trace does not establish that this branch controls selection.

Named `PadGetState` at `0x80094fe0` was entered 600 times with `a0=0` and
return address `0x80064e58`. This is a controller-status caller lead. Its
return, button buffer, and selection field were not captured. It does not
identify a reconstructed menu update loop.

The metadata hook stopped at frame 3970 with zero errors and overflow.
The first attempt expired without a gate and is preserved. In the retry,
initial frame writes failed through frame 1560 because the host output
folder was missing. Frame capture succeeded from 1620 after correction.
This is not a clean whole-run image-capture pass. The principal later
interrupted the process, exit 255. Raw traces, images, scripts and hashes
remain local. No packet or guest-memory payload was captured by this hook.

## Our code and checks

`components/exe/call_8007c11c.cpp` implements the function with injectable
DrawSync, DrawSyncCallback, DrawOTag, and branch-word services. Fixed-width
guest addresses remain separate from host pointers. The branch-word reader
is called after synchronization, preserving the observed load order.

The focused test checks both branches, a word changed during DrawSync,
both observed address calculations, zero-count wrap, and opaque return
propagation. Its checks execute under NDEBUG. Default and optional SDL2
builds passed the test. The existing FRONT.TIM and SDL platform tests also
passed. These are host semantic checks, not retail equivalence or SDK
execution. Callback scheduling and actual list submission belong to the
backend and are not implemented by the test.

This is an implemented submission wrapper. It does not generate menu
geometry, update selection, or connect a complete native game loop.
