# Block at 0x80088458

Traced fact from the USA PS-X EXE. Re-check on a disc you own with `python3 tools/entry_disasm.py build/disc/SLUS_004.91 --start 0x80088458`. The executable and the listing stay in `build/`.

The start address is `0x80088458`. The `beq` in [call-800883ec.md](call-800883ec.md) is this instruction. On a DuckStation fast boot of the USA cue, the first stop at this PC is on that path. `ra` is `0x800883d4`. `s0` is `0x800e160c`. `s1` is `0x40`. `s2` is 0. `s3` is `0x800882c4`. `v1` is `0x1f801814`. `a0` is `0x4000000`. The word at `0x800b76d0` is `0x1f801814`. `v0` is `0x4000000`, which is that `a0` bit of the word loaded through `v1`. The `beq` branches to `0x8008844c` when `v0` is 0. `v0` is not 0, so this boot falls through. The hard cap is 64 instructions. This block ended before the cap.

The delay slot is `nop`. `addu` copies `s0` into `a0`, so `a0` is `0x800e160c`. `jalr` at `0x80088464` jumps through `s3` and sets `ra` to `0x8008846c`. The target is `0x800882c4`. `python3 tools/sdk_match.py` does not name it. The delay slot copies `s2` into `a1`, so `a1` is 0. This note does not enter that body.

After the delay slot, control goes to `0x800882c4`. `a0` is `0x800e160c`. `a1` is 0. `a2` stays `0x40`. `s0`, `s1`, `s2`, and `s3` stay as they arrived. `ra` is `0x8008846c`. The words at `0x8008844c` are not taken. The display x and y halfwords are still not quoted. This note does not close the gap in `components/exe/load.cpp`.
